# 多格图、九宫格与故事板编排及验收作业指导

## 适用与输入

适用多格设计板、联系表、九宫格及故事板的图像编排。layout.grid_3x3表示三行三列共九格，仅是版式；不等于故事板，也不表示平台支持一次生成九张文件。一次生成拼板和多次生成后排板是不同制作方式，按实际模型契约选择并记录。

输入为PR-IMAGE-ROUTING的用途/表达/版式/阶段、对象与母版版本、格数、阅读方向、每格任务、参考职责和下游用途。执行者先确定关系模式，再写逐格内容；没有逐格清单，不以“丰富九宫格”代替设计。

## 一、先确定互斥的关系模式

同一板先选一个模式。需要混合时拆成独立板；确需组合的展示页，应有清楚分区和各区模式，不让同一条阅读链同时承担互相冲突的意义。

| 模式 | 含义 | 每格必须记录 | 禁止误读 |
|---|---|---|---|
| temporal_sequence 时间递进 | 格与格表示有先后关系的状态或镜头 | 序号、镜号或阶段号、时点/顺序、起止状态 | 格序不是自动等间隔，九格不等于九秒 |
| same_time_multiview 同一瞬间多角度 | 同一对象/空间在同一时点从不同方向观察 | 共同状态ID、视角、相机方向、可见/遮挡面 | 角度变化不是动作继续，也不是九个叙事镜头 |
| independent_collection 无时序合集 | 独立表情、服装、道具方案或信息集合 | 每格主题/方案ID、继承项、允许差异 | 排列顺序不暗示角色经历了一段故事 |

角色正侧背通常属于同一状态多视角；表情表通常属于无时序合集；同一角色连续起跳落地的动作表属于时间递进。storyboard_sequence为叙事镜头序列；storyboard为单镜的确定瞬间。故事板每格可来自不同镜头，动作分解每格也可能是同一镜头的不同阶段，必须写清。

## 二、建立逐格状态表

每格一行，不把多个互斥瞬间写在一格。状态表至少含：

| 字段 | 填写要求 |
|---|---|
| cell_id/位置/阅读序号 | 九宫格可用R1C1至R3C3；阅读次序明确，不靠图中标签推断 |
| 用途与模式 | 继承板级用途与关系模式 |
| 镜号/时点/方案ID | 按模式填写；不适用写原因，不编时间 |
| 角色/对象/场景版本 | 全板共有项可引用公共基线，允许变化逐格列出 |
| 身体与道具状态 | 站位、朝向、重心、持有者、接触、开闭与损伤 |
| 相机与轴线 | 位置、高度、朝向、景别及位于轴线哪一侧 |
| 画面信息 | 每格只承担一个主要可见任务 |
| 光源与环境 | 共同状态与有因变化；不能随格重新随机设计 |
| 可见文字 | 精确短标签或无文字；说明文字可置于板外记录 |

时间递进模式逐对检查：前格结束如何成为后格开始；角色或道具转移、门开闭、伤痕和天气变化应有动作或剪辑依据。同一瞬间模式冻结以上状态，只改变观察方向；被遮住不等于对象消失。无时序合集明确哪些差异属于任务，如服装不同，但身份是否共用不能含糊。

## 三、编排与提示词装配

1. 设置行列、总格数、格距、边界与阅读顺序。每格采用一致画幅，或明确例外；人物头顶、鞋底、关键道具与接触点保持可读。格数过多使关键细节无法检查时拆板，不用增大“高清”词频解决。
2. 先写共享身份/空间/风格基线，再按cell_id写差异。角色与场景参考分清职责；每格不得自行发明不同母版。
3. 时间递进使用“第几镜的哪一瞬间”；同一瞬间多视角写共同时点和摄影方向；合集写各格方案与允许变化。只给模式所需信息，不强加戏剧时序。
4. 图像内文字只放必要短标签；完整说明保存在逐格表，避免挤满小字。文本正确与格号对应须看图核对。
5. 输出要求区分单张拼板、独立格图和可编辑排版文件。生成模型无法提供某种交付时，使用已验证后处理流程或标缺项，不把拼板假称独立资产。

### 可复制骨架

```text
制作{用途}的{行数}×{列数}多格板，共{格数}格，阅读顺序{顺序}。
关系模式为{时间递进/同一瞬间多角度/无时序合集}。{说明格与格之间究竟代表什么，不代表什么}。
全板共同基线：角色{ID与身份锚点}，场景{布局版本}，服装/道具{共同结构与状态}，风格和光照{约束}。
参考职责：{实际图序号与身份/布局/服装职责}。
R1C1：{镜号/时点/方案ID}；相机{位置朝向景别}；对象{明确的单一状态}；主要信息{任务}。
{按相同结构逐格列完，不能以“以此类推”省略末格。}
各格边界清楚，不串格，不出现额外人物或额外格。可见文字{准确短标签/无}。
{共享不可变量}保持一致；只允许逐格表明确列出的变化。每格仅有一个瞬间，不在一格重复画同一角色的前后位置。
```

骨架只是设计内容，数量、尺寸、批量、参考输入和格式另由精确模型契约约束。一个九宫格请求不保证正确九格；不得把实际收到八格或十格记录为成功九格。

## 四、可观察验收与拒收

先核板：实际行列/总数、是否缺格/合并格/串格、阅读顺序和标签对应。再逐格核对身份、结构、姿态、接触、文字和裁切；最后按模式检查关系。

- 时间递进：逐对检查镜号、时点、方向、持物与环境；无因跳变、动作阶段倒置、前后互斥状态同格出现，均记录缺陷。越轴若是明确设计必须有依据，不能默认允许。
- 同一瞬间多角度：身体姿态、关节、道具开闭与位置应相同；随视角只改变可见面和遮挡。不对称服饰翻边、背面结构不连接、反打地标换位时拒收。
- 无时序合集：不同格确实表达预定差异，且共用身份/结构不变量。九格几乎相同导致比较目的失效，或用不同人物代替同人表情差异，均需返工。
- 所有模式：格边把关键动作截断、标签与图不对应、额外肢体或穿透接触、关键部位太小无法判定，不得按“整体很好看”放行。

逐项记录cell_id、缺陷位置、预期、实见、严重度、检查者与日期。未检查的格保留not_checked；看过缩略板不等于已完成各格细节验收。实际生成和视觉验证不属于本SOP发布时已完成的事项。

## 五、定点返工与再验收

优先修关系模式或状态表错误，其次身份/空间，再修格数边界与局部表演、材质。局部失败可单独重做该格或在可用编辑入口定点修改，明确保护其他格；不要一次重写所有九格制造新的不确定变化。

例：R2C2的杯子从右手无因换到左手，保留脸、衣装、机位及其他格，只修持握与遮挡；复验R2C1→R2C2→R2C3，确认接续未破坏。若模式原本应为同一瞬间，却写了九个动作阶段，应重写状态表并重做受影响格，不靠调序掩盖。

记录原板SHA、失败格ID、修复提示词SHA、新格或新板SHA、保留项及复验结论。拼回板后重新核对位置和格号，合格单格不等于拼版已合格。

## 六、拆分为视频参考与交付

多格板是设计资产；视频入口是否允许拼板须另查契约。需要单格时为每个衍生图记录父板文件及SHA、cell_id、裁切像素边界、是否去标签/边框、缩放方式、子资产ID/版本/路径/SHA。若重绘或补边，另记编辑任务，不能标为纯裁切。

裁切后检查尺寸、主体完整性、标签残留与新的边缘缺陷；图中原有布局线不得误当场景线条。子图按角色参考、场景参考或指定镜头首尾帧分别登记用途，逐一绑定镜号与状态。父板更新后标记其衍生文件待核对，不自动当作继承新内容。

交付完整逐格表、父板及子图清单、模式、顺序、输入/输出SHA、检查与缺陷记录。此文件为内部通用工艺设计及结构试运行，不声称任何模型具有确定多格一致性或未经验证的跨平台输入能力。



本文件是内部设计与结构试运行规范；模型API仍按精确入口契约选择，实际图像效果尚未验收。
