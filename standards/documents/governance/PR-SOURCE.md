# 来源采集、文件修订与发布程序

## 输入与责任
输入是来源URL/本地路径、检索范围、作者、采集批次和现有登记册。资料维护者保留原件；规范编写者提炼；审查者核对证据和冲突；发布者保存清单。不得以下载完成代替已采纳。
## 步骤
1. 固定来源身份：GitHub origin+commit+file，X原帖ID，其他资料路径+哈希。记录时间、许可和未取得部分。
2. 只读取授权范围；保留privacy。no_ai不得放入模型包；local仅本地调用。附件或归档未提取时明确登记。
3. 按内容哈希找完全重复，保留来源别名；近重复、翻译和语义冲突人工/代理复核，不自动删原文。
4. 将源包拆成规则、程序、SOP、模板、案例和脚本依赖。候选分类不等于批准；对跨层Skill保存原入口到内部文件的映射。
5. 填写来源及文档元数据。每条经验标适用条件；作者宣称实测与本地实测分列。冲突按模型/版本/平台定位，不以热度或星数裁决。
6. 修订采用新版本与变更记录；检查全部反向依赖、旧记录引用及模型隔离，运行doctor和回归。发布到新目录，冲突停止，保存内容哈希清单。
## 输出与异常
输出来源清单、候选映射、冲突表、变更记录和发布清单。抓取失败保留错误与下次入口；未明确许可内容保留引用待审；未知能力不进入已发布SOP。不得覆盖正在运行的X采集批次。
