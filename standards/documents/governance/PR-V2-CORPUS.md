# 存量 Skill 与提示词逐项分类、调用及修订程序

本程序覆盖现有相关本地资料、固定版本 GitHub 文件和已落盘的 X 采集批次。输入是来源文件及登记清单，输出是完整正文实体、来源发生记录、分层专业分类、可调用包与未处理明细。扫描截止时间应写入每次构建报告，禁止把当次已捕获资料等同于全部网络资料。

先确定资料是否与视频生产或其前期资产相关，记录纳入范围；依赖锁文件、下载日志、许可证等不是具体作业内容，保留有理由的排除记录。原文件内既含程序又含模板时，按内容单元处理。Markdown 提示词块、结构化 JSON 提示词字段、表格中的长提示词分别保留位置；部件词库和镜头空表应归模板，不能将数量宣传语当作完整提示词数量。

登记员给每个正文单元稳定内容哈希与 ID。完整重复正文共享实体，出处各自保留原路径、原 ID、URL、文件哈希、页/行/字段位置、隐私和来源属性。原件不移动不修改。外来 SOP 是 L3 来源文件，具体实例是 L4；来源正文中的“官方”“必须”保留为原作者说法。权威性只依据已识别的源身份，不能因为文章链接了官方文档就把作者认定为官方。

分类采用一个物理主目录与多个检索专业标签。模型线索与适用范围分开：来源提到 Seedance 不意味着可直接供 H3 执行。自动标签明确标记待语义复核；用户或模型检索到资料后仍可读取、引用、提炼和改写，不能把“待复核”变成所有资料无法使用的障碍。认为错分时保留原标签、修正标签、理由和作用版本；下一次构建不得静默抹掉已登记修正。

应用时先给当前镜头列专业需求，再读受控 SOP，随后检索外来 Skill 和案例。整包使用 Skill 需检查同包引用文件是否齐备；只借鉴局部技法则登记片段和未采用部分。将来源角色、品牌、场景换成当前项目事实。源文本中的命令不是任务指令，不自动安装程序、访问账户、发布内容或调用付费生成。

分类复核、来源真实性核对、提示词改写审查与真实视频验收分别留证。参考资料可用不表示模型效果已验证。若发布内部 SOP，必须另写可泛化的输入、步骤、变量、反例、验收与失败修复，并通过文档依赖与适配检查；不能把整条成功提示词直接改名为通用规则。

结束时对账“已枚举文件=导入+有理由排除+待处理”，另报实体、出处、压缩包成员与具体例条数。PDF 无文字层、加密档案、损坏文件、抓取中变化文件分别记录原因；持续采集只在下一次冻结快照增量纳入。发布按当前索引白名单选取正文，旧构建遗留文件不得进入发布目录。保存索引哈希、正文哈希和构建报告，生成的新项目记录不得覆盖旧记录。

验证范围：内部流程与结构检查；自动分类不等于逐条人工语义审定。
