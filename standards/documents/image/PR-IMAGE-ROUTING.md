# 图像资产用途、表达与版式路由程序

## 目的与边界

将任何图像需求拆为可组合的设计维度，再调用已有专业规范、提示词模板与精确模型契约。角色图、场景图、分镜图只是常见用途，不是封闭目录。新增用途不应重新建一套质量体系，也不能把一切含九宫格的素材归为同一种作业。

本程序规定创作和质量交接，不规定任何平台必然接受组图、网格、遮罩或多参考输入。构图要求与实际API字段分开；通用设计成立不代表跨模型执行相同。图像实际生成走assets阶段；剧本和镜头计划继续由对应程序管理。

## 输入与责任

需求方说明最终拿图做什么；资产负责人冻结对象与状态；摄影/分镜负责人确认视角、时间和信息顺序；操作者选定平台契约；复核者依据实际画面验收。可一人兼任，但记录不能把准备、生成成功与视觉合格合并成一个状态。

最低输入为：用途、对象ID及版本、希望表达的信息、交付载体、是否已有参考、哪些不可改变。缺少明确需求但可安全选择的事项，由操作者写明假设继续准备；身份母版、关键道具结构、时间关系等会改变正确性的缺项，先标未解决，不把猜测当作批准设定。

## 一、分别记录五个维度

| 维度 | 回答的问题 | 记录示例与边界 |
|---|---|---|
| 用途 | 成品用于哪项生产工作 | 道具设计、角色身份、单镜分镜、故事板；用途不由格数决定 |
| 表达内容 | 要看清什么关系或变化 | 身份、几何结构、表情、动作阶段、空间关系、材质、文字信息 |
| 版式 | 信息在画布上怎么排 | 单画面、并列视图、联系表、layout.grid_3x3、带标注板；不代表时间顺序 |
| 生产阶段 | 当前产物的成熟度与下游 | 探索、设定冻结、镜头预演、生成参考、修复、交付；探索图不能直接当批准母版 |
| 模型契约 | 哪个具体入口执行 | model/version/platform/mode、参考数量、尺寸格式、输出方式、执行验证状态 |

“九宫格故事板”至少包含用途storyboard_sequence、叙事状态表达、版式layout.grid_3x3；“九宫格表情图”则是表情用途及状态合集。同样版式可跨用途，同样用途可用不同版式。保留这些独立字段，禁止只登记一个“九宫图”标签而丢失语义。

## 二、开放用途及所需验收对象

以下为路由起点，不是完整世界分类。标识用于语义说明，实际调用名以注册表为准；不存在的标识不得伪装成已实现CLI参数。

| 用途 | 必须表达的内容 | 关键验收对象 |
|---|---|---|
| 角色身份图 | 脸型、比例、发型、识别标记 | 与母版对应且关键部位可辨 |
| 三视图/多视图 | 正侧背或明确角度的结构对应 | 同尺度、身体左右、隐藏面连接 |
| 表情图 | 眼睑、眉唇、视线、面部张力 | 身份不变，指定状态可区分，不只贴情绪标签 |
| 姿态/动作参考 | 支撑、重心、接触、动作阶段 | 肢体成立，阶段关系明确，非随意漂亮姿势 |
| 服装造型 | 款式、裁片、配饰、穿着状态 | 前后结构和身体侧别一致，不擅改角色身份 |
| 道具图 | 外形、尺寸、结构、功能、持握区 | 可操作部件与开闭状态合理，接触尺寸能用 |
| 载具/生物 | 整体比例、关节或活动机构 | 可动部位及乘坐/负重/运动支撑关系成立 |
| 场景图 | 固定地标、光源、尺度、活动空间 | 反打拓扑相容，剧情路线可通过 |
| 空间平面/布局图 | 方位、入口、区域、路径、比例关系 | 标注对应实际布局；概念示意不冒充工程测量图 |
| 氛围图 | 时间、天气、色彩、光源、环境状态 | 能支持目标情境，不代替缺失的空间结构图 |
| 材质/表面图 | 粗糙、反光、透光、纹理尺度 | 同一材质跨部位一致，贴图用途另查技术规格 |
| 单镜分镜图（storyboard） | 单一镜号中的一个确定瞬间 | 机位、轴线、持物、遮挡、信息任务 |
| 故事板（storyboard_sequence） | 多个有序镜头的叙事关系 | 镜号、顺序、跨镜身份/场景/道具状态 |
| 关键帧/首尾帧 | 明确时点的起态或终态 | 两态与计划动作相容，不以两张美图证明可连接 |
| 风格板 | 颜色、形状、光影、材质的视觉方向 | 各参考职责明确；不默认移植品牌或原有角色 |
| 特效设计 | 起点、形态、遮挡、接触、阶段 | 当前效应与物体及空间关系成立，非任意光团 |
| 图文宣传/海报 | 信息层级、文字、主体与留白 | 文字逐字正确，视觉资产及宣传事实有依据 |
| 其他/复合用途 | 用户实际下游与必需信息 | 拆出主用途及从属用途；记录专门验收点 |

## 三、路由与来源选择

1. 确认主用途和下游；复合任务拆成可验收的子产物。例如人物、服装、表情和动作表需要共同身份基线，但不必挤在一张低可读性画布中。
2. 列表达内容及不变量，再选版式。需要九格时先使用SOP-IMAGE-MULTIPANEL确定其时间关系，不能从九格直接推断“九个镜头”。
3. 选择最少必要专业规范。已有角色、场景、摄影、表演、道具和连续性要求继续复用；某项不适用记原因，不无条件载入全部规范。
4. 搜索来源时先按用途及表达匹配，再按版式和风格比较。阅读候选正文，记录来源ID、路径、commit/版本、正文SHA、采用内容和排除内容。来源缺图、未审或只有作者声称时保留其状态。
5. 提取方法并替换项目变量；不得默认继承案例品牌、人物、台词、场景地名、互动数据或水印。模板数量和比例只是设计选项，不是平台能力或固定生产要求。
6. 根据参考是否真实存在和目标改动选择精确模型契约。契约缺失时可完成设计准备，但不能使用相似名称猜参数或静默换平台。

## 四、组包、验证与发布

输出路由记录、子产物清单、完整提示词、独立参数、参考职责与验收条目；记录FR-IMAGE-JOB。参考逐张标顺序、实际路径、SHA及身份/服装/布局/材质等职责。描述中的图号与上传序号一致，缺图不得填虚构路径。

实际生成后依据用途逐项看图，并使用FR-IMAGE-INSPECTION记录具体部位、格号或地标。关键缺陷包括身份漂移、结构不成立、功能接触不可能、空间矛盾、叙事顺序错误及目标文字错误。参数合法、文件可解码、图像美观不能代替这些内容检查。发布时明确“用于探索”“已批准设计参考”或“可供某镜使用”，不得笼统写全部可用。

## 五、未覆盖用途与持续修订

若无匹配SOP，不将需求硬塞进人物/场景四类。登记真实用途名称、表达内容、版式、下游、缺失规范和临时验收点；可复用部分继续准备，未覆盖部分标review。仅当补齐输入、步骤、可观察验收、失败处理、记录接口后，才将临时方法提升为受控SOP并建立模板。扩大用途目录不代表模型资格同步扩大。

发现分类错误保留原来源与旧判断，记录修正理由及影响范围。修复图像时先定位失败维度：需求或用途错回路由，结构错回设计，参数错回契约，局部画面错做定点返工。复验同时检查目标缺陷与被保护区域；影响多个子产物时按版本清单重新核对，不删除失败图掩盖过程。

## 输出记录与验证状态

记录route_id、用途、表达内容、版式、阶段、精确模型元组、所选SOP/模板版本、采用来源、输入SHA、输出SHA、缺陷与复验关联。未生成仅能记录设计或请求准备完成；本程序为内部设计及结构试运行，未据此执行API或验证生成质量。


本文件是内部设计与结构试运行规范；模型API仍按精确入口契约选择，实际图像效果尚未验收。
